# Dynamic Rendering (Query-Index-Driven Content)

Several content lists on this site are **dynamic**: instead of hand-placed cards
and links, they read the site's `query-index.json` (auto-generated by AEM from
published pages) and render from it. Add or remove a page and the list updates
automatically once the index rebuilds — no page edits required.

This is the same query-index mechanism the header search uses.

## Where it's used

| # | Location | Lists | Config | Implemented by |
|---|----------|-------|--------|----------------|
| 1 | **Magazine → "All Articles"** | all magazine articles | prefix `/us/en/magazine`, sort `title`, no limit | `cards-index` block |
| 2 | **Homepage → "Recent Articles"** | magazine articles | `/us/en/magazine`, sort `newest`, limit `4` | `cards-index` block |
| 3 | **Homepage → "Where do you want to go?"** | adventures | `/us/en/adventures`, sort `newest`, limit `4` | `cards-index` block |
| 4 | **Every article page → "Share this story"** | related articles in the same section | same section, current page excluded, sort `newest`, limit `4` | `scripts.js` |

## How it works

```
Author adds/removes a page in Document Authoring (DA)
        │  previews / publishes it
        ▼
AEM regenerates /query-index.json  (per helix-query.yaml)
        ▼
Block / script fetches query-index.json → filter (section prefix)
        → sort (title | newest) → limit → exclude landing/self
        ▼
Renders cards / links → the list updates on its own
```

- **`query-index.json`** is not a file in the repo or DA — AEM builds it and
  serves it at a URL (e.g. `.../query-index.json`). Its columns are defined in
  [`helix-query.yaml`](../helix-query.yaml): `path`, `title`, `description`,
  `image`, `lastModified`, `content`.

## The code

### `blocks/cards-index/` — reusable dynamic grid (locations 1–3)

Reads the index, filters to a section prefix, sorts, limits, and excludes the
section landing page. It **reuses the `cards-teaser` block** for all styling:
it builds the cards-teaser DOM and delegates to its `decorate()`.

Authored via the block table (all rows optional):

| cards-index |               |
|-------------|---------------|
| prefix      | /us/en/magazine |
| sort        | newest        |
| limit       | 4             |

- `prefix` (aliases: `path`, `section`) — section to list. If omitted, it is
  auto-detected from the current page's path (`/{country}/{lang}/{section}`).
- `sort` — `title` (default, A→Z) or `newest` (by `lastModified`, desc).
- `limit` — max cards (default: all).
- A single-cell row containing just the prefix is also accepted as shorthand.

Robustness: the index fetch uses a per-minute cache-buster, and an **empty**
result is not cached (so a transient stale-CDN response doesn't blank every
grid on the page).

### `scripts.js` — dynamic article related list (location 4)

`decorateArticleTeasers()` detects the article sidebar's related list and calls
`populateRelatedArticles()`, which refills it from the index (same section,
current page excluded, newest, limit 4). This fixed the source's bug where every
article linked to itself. The authored list is kept as a fallback if the index
can't be loaded, and the existing `.related-articles` markup/styling is reused.

## Not applied here (by design)

- **Adventures listing page** — its category tabs (Climbing/Surfing/…) need a
  field the query index doesn't carry, so it stays authored.
- **About Us contributor bios** — static bios, not links to indexed pages.
- **FAQs** — no lists of indexed pages.

## Known limitation: dates

List "date" lines depend on the index's `lastModified` field, which currently
comes back empty from the aem.live indexer (despite the `helix-query.yaml`
format fix). The code handles this gracefully — the date line is omitted rather
than showing a wrong value, and `sort=newest` falls back to alphabetical. Dates
and true newest-first ordering appear automatically if/when `lastModified`
starts populating.
