# Dynamic Rendering (Query-Index-Driven Content)

Several content lists on this site are **dynamic**: instead of hand-placed cards
and links, they read the site's `query-index.json` (auto-generated by AEM from
published pages) and render from it. Add or remove a page and the list updates
automatically once the index rebuilds — no page edits required.

This is the same query-index mechanism the header search uses.

### Sheet-driven listings (Magazine + Adventures)

Two listings read hand-authored DA **sheets** rather than the auto query-index,
giving authors full control (exact items, order, and — for Adventures —
categories):

- **Magazine "All Articles"** → `cards-articles-wknd` reads
  `/us/en/magazine/query-index.json` (columns `path/title/description/image`),
  rendering cards in authored order.
- **Adventures "Current Adventures"** → `cards-adventures-wknd` reads
  `/us/en/adventures/query-index.json` (adds a `category` column) and builds the
  All/Climbing/Cycling/Skiing/Surfing/Travel filter tabs from the distinct
  categories, filtering cards client-side. This is something the auto
  query-index could not do — it has no per-page category field.

Both are edited in the da.live sheet grid (no `.xlsx`; served as JSON,
`:type: sheet`) and reuse `cards-teaser` for card styling. Trade-off: sheet-
driven lists are curated, so new pages do **not** auto-appear — the author adds
a row.

### Two data-source modes (cards-index)

The `cards-index` block supports two sources, chosen by the authored value:

- **Auto query-index (prefix):** a path/section (e.g. `/us/en/adventures`) →
  fetches the AEM-generated `/query-index.json`, filters to that section, sorts,
  and excludes the landing page. New pages appear automatically (locations 2–4).
- **Hand-authored data sheet (`.json` URL):** a value ending in `.json`
  (e.g. `/us/en/magazine/query-index.json`) → fetches that DA **sheet** directly
  and renders its rows in authored order. Full curation control; the author
  maintains the sheet (location 1). In Document Authoring a "sheet" is created in
  the DA editor and served as JSON (`:type: sheet`) with column headers
  (`path`, `title`, `description`, `image`) — there is no `.xlsx` file in DA.

The **`cards-articles-wknd`** block is a thin named wrapper around `cards-index`
used on the Magazine page so authors see a meaningful block label; all logic and
styling are delegated (no duplication).

## How it works

```
Author adds/removes a page in Document Authoring (DA)
        │  previews / publishes it
        ▼
AEM regenerates /query-index.json  (per helix-query.yaml)
        ▼
Block / script fetches query-index.json → filter (section prefix)
        → sort (title | newest) → limit → exclude landing/self
        ▼
Renders cards / links → the list updates on its own
```

- **`query-index.json`** is not a file in the repo or DA — AEM builds it and
  serves it at a URL (e.g. `.../query-index.json`). Its columns are defined in
  [`helix-query.yaml`](../helix-query.yaml): `path`, `title`, `description`,
  `image`, `lastModified`, `content`.

## The code

### `blocks/cards-index/` — reusable dynamic grid (locations 1–3)

Reads the index, filters to a section prefix, sorts, limits, and excludes the
section landing page. It **reuses the `cards-teaser` block** for all styling:
it builds the cards-teaser DOM and delegates to its `decorate()`.

Authored via the block table (all rows optional):

| cards-index |               |
|-------------|---------------|
| prefix      | /us/en/magazine |
| sort        | newest        |
| limit       | 4             |

- `prefix` (aliases: `path`, `section`) — section to list. If omitted, it is
  auto-detected from the current page's path (`/{country}/{lang}/{section}`).
- `sort` — `title` (default, A→Z) or `newest` (by `lastModified`, desc).
- `limit` — max cards (default: all).
- A single-cell row containing just the prefix is also accepted as shorthand.

Robustness: the index fetch uses a per-minute cache-buster, and an **empty**
result is not cached (so a transient stale-CDN response doesn't blank every
grid on the page).

### `scripts.js` — dynamic article related list (location 4)

`decorateArticleTeasers()` detects the article sidebar's related list and calls
`populateRelatedArticles()`, which refills it from the index (same section,
current page excluded, newest, limit 4). This fixed the source's bug where every
article linked to itself. The authored list is kept as a fallback if the index
can't be loaded, and the existing `.related-articles` markup/styling is reused.

## Not applied here (by design)

- **Adventures listing page** — its category tabs (Climbing/Surfing/…) need a
  field the query index doesn't carry, so it stays authored.
- **About Us contributor bios** — static bios, not links to indexed pages.
- **FAQs** — no lists of indexed pages.

## Dates & newest-first

List "date" lines and `sort=newest` use the index's `lastModified` field.

This is populated in [`helix-query.yaml`](../helix-query.yaml) via
`parseTimestamp(headers["last-modified"], "ddd, DD MMM YYYY hh:mm:ss GMT")`.
Note the **square-bracket** header accessor (`headers[...]`) — the
function-call form `headers(...)` silently returns nothing and leaves the field
empty. `lastModified` is the page's last **publish** time (from the
`last-modified` response header), expressed as UNIX seconds.

Because `last-modified` reflects publish time, pages published together share
the same value; `sort=newest` tiebreaks to title order in that case, and spreads
out as pages are edited/published individually. If `lastModified` is ever
missing, the code degrades gracefully — the date line is omitted (not shown
wrong) and sorting falls back to title.
