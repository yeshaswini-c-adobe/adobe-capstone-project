01Executive Summary

WKND is a well-structured Adobe Experience Manager (AEM) Sites reference site built on Core Components, Experience Fragments, and a DAM-backed asset model. It is an excellent candidate for migration to Edge Delivery Services: content is template-driven, block boundaries are clean, and there are no transactional or personalization dependencies in scope.

Headline findings:

  • Clean template structure. Six templates cover all 64 pages; the two content-heavy types (adventure-detail at 32 pages, article-detail at 12 pages) account for the bulk of content and are highly repetitive — ideal for template-based bulk import.
  • Standard block palette. 24 of 31 variants map to standard EDS blocks (hero, cards, carousel, tabs, accordion, quote, breadcrumbs). Only 7 variants are "unknown" and need custom block work — all are simple heading/image/CTA compositions.
  • Header is the single biggest effort item (advanced nav with dropdowns, search, language picker → 16–32h). Footer is trivial (~1h).
  • Multi-locale via hreflang. 11 locales are declared; only US-EN and CA-EN are fully built out (26 + 29 pages). The other 9 locales are single landing pages.
  • No blocking risks. No login walls, no client-side-only rendering, no anti-bot protection encountered; crawl succeeded at 100% with zero failures.
This report was produced from an automated crawl + per-page structural analysis of the live site. Where noted, SEO/asset metrics are sampled from representative pages of each template and extrapolated.

10Content Modeling Recommendations

  • Adventure & Article metadata → block or metadata table. The structured metadata on adventure pages (activity, duration, price, difficulty) should be modeled as a dedicated metadata/fact-sheet block so authors edit named fields rather than free text.
  • Teasers → cards. The recurring "featured teaser grid" on homepage/section-landing should standardize on a single cards block content model (image + title + description + link) rather than the 7 ad-hoc "unknown" compositions.
  • Related content → auto-block. "Related adventures / related articles" should be an auto-block driven by an index (query-index.json) rather than hand-authored links, to keep them fresh.
  • FAQ → accordion. Direct map; one row per Q/A.
  • Consistent section styling via Section Metadata (e.g. Style: highlight) instead of bespoke block variants.

14DAM Recommendations

  • De-duplicate on the shared pool. Assets live under wknd-shared and are reused across locales — migrate the pool once, reference everywhere; do not copy per-locale.
  • Let EDS handle renditions. Drop AEM's manual .coreimg rendition chain; EDS generates responsive/next-gen formats automatically. Upload highest-quality originals.
  • Optimize before commit. Any asset committed to git (icons, logos) must be compressed and size-checked per EDS performance guidance.
  • Preserve alt text. Capture existing alt attributes during import for accessibility and SEO parity.
  • SVG logos → /icons. Standardize icon usage via the EDS icon convention.

17Internal Linking Analysis

  • Header nav exposes ~20 links: top adventures, magazine articles, about, faqs — a curated set, not the full catalog.
  • Detail pages carry ~13 internal links each (breadcrumbs + related content + nav), plus ~9 external links (social/partners).
  • Breadcrumbs appear on 44 pages — the deepest-reused block; must resolve correctly against new extensionless paths.
  • All internal links are locale-scoped (/us/en/…), so link rewriting during import can be done per-locale with a simple prefix map.
  • Action: rewrite .html links to extensionless and validate no orphan pages after import (every page should be reachable from nav or a listing).

21Authoring Model Recommendations

  • Document-based authoring (Google Docs / Word or Document Authoring) fits WKND's editorial content (adventures, articles) best.
  • One document per page, mirrored per locale under /{country}/{lang}/… — matches the existing structure exactly.
  • Structured fields as block tables so non-technical authors fill named cells (activity, price, difficulty) instead of formatting prose.
  • Shared nav & footer documents per locale; a language-picker driven by the locale path.
  • Spreadsheet for redirects and for any index-driven listings.

25Phase-wise Migration Plan

Week 1

Phase 0 — Foundation

Provision EDS project (boilerplate), configure content source (Document Authoring), fstab/mountpoint, CI code-sync, baseline styles & fonts. Set up preview/live environments.
Week 1–2

Phase 1 — Global chrome & core blocks

Build header (nav, dropdowns, language-picker, mobile, search plan) + footer. Implement standard blocks: hero, cards, carousel, tabs, accordion, quote, breadcrumbs. Validate each with a representative page.
Week 2–3

Phase 2 — High-volume content import

Generate import infrastructure for adventure-detail (32) and article-detail (12); define metadata blocks; bulk-import US-EN then CA-EN. Migrate DAM assets. Rewrite links extensionless.
Week 3–4

Phase 3 — Landing pages & locales

Import homepage, section-landing, adventures-listing, faq pages. Add 9 locale landing pages. Wire related-content auto-blocks and listings.
Week 4–5

Phase 4 — SEO, QA & hardening

301 redirect map, hreflang parity, sitemap generation, metadata sweep. Visual parity QA across all 6 templates. PageSpeed tuning toward 100. Accessibility (WCAG 2.1 AA) pass.
Week 5

Phase 5 — Go-live

Stakeholder sign-off, DNS/publish, redirect activation, post-launch monitoring.

26Dependencies

  • Access to source DAM originals (or ability to re-download high-res assets from wknd-shared).
  • Confirmed content source decision (Document Authoring vs Google Drive/SharePoint) and org/site provisioning.
  • GitHub repo + AEM Code Sync (Helix Bot) installed and authorized.
  • DNS / hosting cutover ownership and redirect deployment authority.
  • Stakeholder decision on locale scope (full parity vs landing-only for the 9 minor locales).
  • Header/nav design sign-off (search behavior, language-picker UX) before Phase 1.
  • Final URL strategy sign-off (extensionless + country/lang prefix retained).

27Assumptions

  • Scope = the 64 crawled pages + 1 PDF; no gated/authenticated content beyond the public members-only articles that returned 200.
  • US-EN and CA-EN are the primary build; other 9 locales migrate as single landing pages unless expanded.
  • No e-commerce, forms-processing, or personalization is in scope (none detected).
  • Search may be delivered as client-side index search or deferred post-launch.
  • Structured data (JSON-LD) is currently absent and treated as an enhancement, not a parity requirement.
  • SEO metrics for non-sampled pages are extrapolated from representative pages of each template.
  • Effort assumes 1–2 experienced EDS developers and available design references.
