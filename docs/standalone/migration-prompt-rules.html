Purpose how this migration was driven

This page documents the working rules and prompt workflow that actually drove the WKND → Edge Delivery Services migration — the plan→execute discipline, the skills used at each stage, and the verify-before-publish gates. It is a lessons-learned reference so the same approach can be repeated for the remaining locales or a new site.

One-line rule

Plan in read-only mode → confirm scope → execute one template end-to-end → verify on preview → publish. Never bulk-publish unverified; never hand-edit generated content.

Plan → Execute Discipline mode rules

  • Start in Plan mode for anything non-trivial — gather facts with read-only tools, produce a checklist artifact, and get scope confirmed before writing.
  • Ask before assuming — when scope, URLs, or design choices are ambiguous, ask a structured question rather than guess.
  • Switch to Execute only once the plan is agreed; then implement the checklist in order.
  • One template at a time — fully solve and verify a template before moving to the next.
  • Verify with evidence — inspect real DOM/markup (curl, preview) before claiming something works; report failures honestly.

Prompt Writing Rules how to phrase work

  • State the target artifact — name the exact file/template/URL, not "the page".
  • Give the contract — for a block, specify the initial content structure (what the author writes) before the decorated output.
  • Constrain scope — one block, one template, or one fix per prompt; avoid "do everything".
  • Demand verification — ask for the change to be confirmed against real rendering, and for honest failure reporting.
  • Prefer reuse — "reuse an existing base block / Block Collection reference" over "build new".
  • Keep credentials out — never paste tokens; rely on injected auth.
Template

"In [Plan/Execute] mode, for <template/URL>: [goal]. Reuse <base block>. Expected structure: [contract]. Verify on preview against the source and report honestly."

Quality Gates & Honesty guardrails

  • Preview before live — every page validated on *.aem.page against the source before publishing to *.aem.live.
  • Lint must pass — npm run lint green before commit.
  • Deterministic & reversible — re-run a fixed parser to reproduce; Git history is the audit trail.
  • Don't hand-edit generated content — regenerate via the import script instead.
  • Report reality — state discovered vs. migrated counts honestly; record coverage gaps rather than hide them.
Applied here

These rules produced: 27 pages migrated (US/EN full tree), 6 templates, 13 reusable blocks, 0 defects, PageSpeed 100 — with a documented homepage coverage gap and honest discovered-vs-migrated counts. See the assessment.
