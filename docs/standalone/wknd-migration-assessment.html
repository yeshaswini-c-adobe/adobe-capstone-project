Executive Summary what & why

WKND is a template-driven Adobe Experience Manager Sites reference site (Core Components, Experience Fragments, DAM assets). It was migrated to Edge Delivery Services (EDS) with content authored in Document Authoring (da.live). Clean block boundaries and repetitive templates made it an ideal candidate — no transactional or personalization dependencies were in scope.

Headline

64 pages analyzed across the live site → 27 US/EN + CA/EN pages chosen for the build, covering 6 templates and delivered with 13 EDS blocks. Migration ran template-by-template through a repeatable parser → transformer → import pipeline. Result: 100% of in-scope pages live, 0 open defects, PageSpeed 100.

Page Analysis discovery

A full crawl of wknd.site discovered and structurally analyzed 64 pages (100% success — no login walls, client-only rendering, or anti-bot). Each page was decomposed into sections and blocks, then grouped by structural signature into templates.

Where Migration Started entry point

Migration began with the most repetitive, highest-volume template first — adventure-detail (32 pages). Nailing the biggest, most uniform type early validated the whole pipeline (parser → transformer → import) against the most content, so the remaining five templates reused a proven engine.

Why start here

A single adventure-detail structure (hero + fact sheet + body + related) repeats across 32 pages. Getting one parser right immediately covered half the content and de-risked every later template.

Foundations laid before page migration

  • Design system — fonts, color tokens, spacing extracted from the source into styles.css.
  • Global header & footer — nav (dropdowns, search, language picker) and footer built and published on the serving branch.
  • Content source — da.live mounted via fstab.yaml; helix-query.yaml set up to index pages.

Consolidation

The source's 31 variants were consolidated to this lean set; 3 dead base blocks (columns, table, hero) had zero content instances and were removed. See the Block Reusability Audit.

Migration Approach principles

  • Template-first, highest-volume-first — start where one parser covers the most pages (adventure-detail, 32), then reuse the engine.
  • Reuse over custom — every block derives from a Block Collection base; no bespoke one-off blocks.
  • Config over code — new adventure/article pages need no developer; listings are query-index-driven (see Dynamic Rendering).
  • Repeatable pipeline — parser + transformer + import script per template, driven by URL lists, with per-page reports.
  • Verify before publish — preview → in-browser validation → publish to live.
