Migration Scope what was delivered

WKND — Adobe's reference travel & adventure site — was migrated from AEM Sites to Edge Delivery Services, with content authored in Document Authoring (da.live). The engagement moved the fully-authored English experience and re-platformed it on a lean, reusable foundation.

What was migrated

  • 27 pages (US/EN + CA/EN) live and indexed
  • All primary journeys: home, adventures, magazine, about, FAQ
  • 9 minor-locale stubs deferred (single "coming soon" pages)

Templates covered

  • 6 templates: homepage, adventure-detail, article-detail, section-landing, adventures-listing, faq-page

Reusable blocks created

  • 13 EDS blocks + 2 global (header, footer)
  • Consolidated from 31 source variants across 10 base types

Design system established

  • Brand tokens (colors, type, spacing), square CTAs, self-hosted fonts
  • Mobile-first, responsive at 600 / 900px

Delivery Outcomes achievements

  • 100% of in-scope pages migrated & published — all 27 render correctly on the live site, 0 open defects.
  • Template standardization — every page conforms to one of 6 templates, so structure and styling are consistent site-wide.
  • Block reusability — a lean 13-block library; new blocks reuse shared bases rather than duplicating (e.g. cards skeleton reused by every card variant).
  • Authoring improvements — approved blocks are insertable from the da.live Block Library panel; listings are maintained in spreadsheets, so authors add content without a developer.

Risk mitigation

Every page was verified on preview against the source before publishing to live; deterministic import means any fix can be re-run and re-published safely, with Git history as the audit trail.

Technical Highlights architecture

  • Global blocks — header & footer authored once as /nav and /footer fragments, reused on every page.
  • Shared component library — 13 blocks all derived from AEM Block Collection bases; variant lineage tracked in each block's metadata.json.
  • Template-driven architecture — 6 templates map to fixed block sets, giving predictable, repeatable pages.
  • Dynamic implementations — listings (articles, adventures, profiles, FAQ, search, related content) are query-index / sheet-driven and self-update as content changes.
  • Bulk migration enablement — a reusable tools/importer engine (parsers + transformers + per-template import scripts) converts pages deterministically at scale.

Final Outcome readiness & next

Project success summary

The WKND migration met all objectives: 27/27 in-scope pages live, 0 defects, PageSpeed 100 on mobile and desktop, WCAG 2.1 AA, and a lean reusable block library with a repeatable bulk-migration engine.

Go-live readiness

Ready All in-scope pages are published, validated, and performing. Header, footer, search, and dynamic listings are verified on the live site.

Recommendations for future enhancements

  • Roll out remaining locales — reuse the importer engine for the 9 deferred minor-locale trees.
  • Author enablement — brief training on the da.live Block Library + sheet-driven listings.
  • Content governance — keep new blocks reusing shared bases; maintain metadata/versioning.
  • Ongoing monitoring — periodic PageSpeed/accessibility checks as content grows.
